A new `beszelscope check` command, plus fixes to the tools' answers and to the command line.

## Breaking changes

- `token status` is gone; run `beszelscope check` instead, on any system.
- The `token` commands (`set`, `list`, `delete`) are built only for macOS, where the Keychain is. On Linux and Windows the binary has no Keychain code, and `token` is an unknown command; the token comes from `BESZELSCOPE_TOKEN` there, as before.
- `version` or `help` with extra arguments is an error.

## Tools

- `metric_history temp` reports the warmest sensor when every sensor reads below zero, instead of 0.
- `fleet_status` counts a system whose status Beszel does not define under a new `counts.unknown`, so the counts add up. The system still gets an "unknown status" problem.
- An operating system code Beszel does not define shows as `unknown (os N)`, not an empty name.
- A telemetry resource attribute that cannot be read (such as a malformed `OTEL_RESOURCE_ATTRIBUTES`) is a startup warning; it never stops the server.

## Command line

- New `beszelscope check`, on every system: shows the hub, where the token comes from and when it expires, then checks both with the hub.
- `go install ...@v0.2.0` builds now report their version, instead of `dev`, in `beszelscope version` and to the AI app.
- Help asked for with `-h`, `--help` or `help` goes to stdout, so it pipes into `less`.
- `beszelscope --version` works.

## Install

One binary per platform, built by GitHub Actions from this tag: `darwin_arm64` (Apple silicon), `linux_arm64`, `linux_amd64`, `windows_arm64` and `windows_amd64`.

1. Download yours and check it was built by this repo's release workflow:

   ```sh
   gh release download v0.2.0 -R agrmohit/beszelscope -p '*_<platform>*'
   gh attestation verify <file> -R agrmohit/beszelscope --signer-workflow agrmohit/beszelscope/.github/workflows/release.yml
   ```

   Or compare its SHA-256 with its line in `checksums.txt`.

2. Rename it to `beszelscope` (keep the `.exe` on Windows) and move it to a folder on your `PATH`. On macOS and Linux, make it executable with `chmod +x beszelscope`.
3. The binaries are not code signed, so a copy downloaded with a browser is flagged on first run. Clear the flag with `xattr -d com.apple.quarantine <file>` on macOS, or `Unblock-File <file>` in PowerShell on Windows. Copies fetched with `gh` or `curl` are not flagged.

Or install with Go 1.27 or later: `go install github.com/agrmohit/beszelscope/cmd/beszelscope@v0.2.0`.

Then follow [Connect it to your hub](https://github.com/agrmohit/beszelscope#connect-it-to-your-hub).
